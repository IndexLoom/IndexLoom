# Persistent tracker sessions (Stage A / A13)

Each configured indexer instance owns a separate reqwest cookie provider. Cookies
are never global request headers. The provider retains host-only/domain scope,
path, Secure, HttpOnly, SameSite, values and absolute expiration times. Max-Age
takes precedence over Expires and is converted to an absolute deadline once, on
receipt. Restarting does not renew it. Cookies without a server deadline receive
a 12-day application-session deadline; longer server deadlines are capped at 12
days. Expired cookies are never sent, and deletion cookies remove saved values.
The jar accepts at most 128 cookies of 4 KiB each, with a 1 MiB snapshot limit.

Migration `0010_tracker_sessions.sql` adds one encrypted snapshot per instance,
with cascading deletion and an expiry index. Storage uses the existing master
key and XChaCha20-Poly1305 facilities with fresh random nonces. Associated data
authenticates the payload purpose/version, indexer ID, configuration revision and
eviction deadline. Cookie attributes and values are all inside the ciphertext.
Keep the existing master key when restarting or restoring a database backup.
No additional token or key file is created.

Configuration saves increment the instance's session revision and delete its
saved session in the same transaction. Conditional session upserts prevent an
in-flight request with old credentials from resurrecting that session. This is
conservative: saving other configuration values also revokes the login. Different
indexers write independent rows through SQLite's existing WAL pool/busy timeout.
Operations on one executor are serialized so authentication and cookie rotation
cannot race on that jar.

Sessions load lazily before the first authentication/request. Restored cookies
use the definition's authentication test when available; rejection falls back to
a fresh login. A request rejected with HTTP 401/403 clears the session and retries
once. Definitions without an authentication test rely on the next request's
status to detect rejection. A tracker returning a login page with HTTP 200 can
only be reliably detected when its definition supplies an authentication test.
Form login continues to retrieve fresh hidden CSRF inputs and use the same jar
for the login page and form submission.

Successful authentication and completed operations write through before returning,
including rotation/deletion cookies from HTTP responses. No shutdown flush or
background writer is needed. Existing graceful HTTP shutdown drains requests;
cache eviction or dropping application state does not delete saved sessions.
Storage evicts expired rows when opening the database and before session reads.
Cryptographic/storage failures fail the operation with a static, redacted error.

Session snapshots have redacted Debug implementations and no API serialization.
Management GET responses do not include runtime cookies. The cookie provider
avoids the upstream cookie-store response helper that logs plaintext cookies.
Cookie headers generated by the provider are marked sensitive. Browser-solver
cookies pass through the same scoped provider in both directions.

Manually configured cookie credentials are seeded once as host-only cookies for
the primary definition URL (Secure on HTTPS). Raw `Cookie` headers declared in
definition request headers are rejected, since they bypass jar scope; use the
indexer's cookie credential setting. Requests/redirects retain the existing
allowed-origin and direct-connection address policy. A bundled Mozilla Public
Suffix List also rejects public-suffix cookie domains. Its original MPL-2.0
notice is retained in `crates/indexloom-engine/data/public_suffix_list.dat`;
refresh it from https://publicsuffix.org/list/public_suffix_list.dat as needed.

## Verification

```sh
cargo fmt --all -- --check
CARGO_BUILD_JOBS=1 cargo test -p indexloom-definitions -p indexloom-engine -p indexloom-storage -p indexloom-server -p indexloom-native --offline
# Refactored Cardigann wire tests explicitly require a loopback-capable runner:
CARGO_BUILD_JOBS=1 cargo test -p indexloom-engine --offline cardigann::wire_tests -- --ignored
```

Tests cover authenticated metadata/ciphertext tampering, wrong keys, database
reopening, expiry/eviction, credential revision fencing, redaction and concurrent
SQLite writers. Cookie tests cover scope, expiry, deletion, prefixes, downgrade
protection, public suffixes, bounds, browser-solver conversion and attribute
injection. Paginated searches use the same session lifecycle as ordinary searches;
rendered Cookie headers cannot replace scoped cookies. Lifecycle tests
also exercise load-before-authentication and immediate persistence without sockets.
Server integration tests use a loopback mock HTTP proxy with a synthetic tracker
hostname and fixture credentials, exercising form CSRF, two accounts on the same
tracker, cookie rotation, restart reuse and remote rejection. They require local
TCP sockets; they never connect to private trackers or external hosts.

Implementation is independent Rust; Prowlarr's indexer-status/expiry behavior and
Jackett's cookie-update behavior were read as references without copying source.
